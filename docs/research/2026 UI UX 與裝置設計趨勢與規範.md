# 2025–2026 UI／UX 與裝置設計趨勢・官方指南整理（設計稽核用）

**產品脈絡**：台灣國中生學習 App。學生端＝手機優先 PWA；老師端＝平板／桌機；家長端＝只用 LINE。品牌色松綠／珊瑚／蜂蜜金、燕麥底；支援深色模式，22:30 自動轉暗；遊戲化冒險世界。
**研究方式**：WebSearch 摘要多來源交叉（2026-10-01 查詢）。可信度：高＝官方文件／多個一手來源一致；中＝主流媒體或單一一手來源；低＝二手部落格或推估。
**用語約定**：「檢查項」＝可直接打勾的具體動作；優先級 P0＝上線前必修，P1＝下一版，P2＝加分。

## 1. Apple：iOS 26／iPadOS 26 與 HIG 2025

### 1.1 Liquid Glass 設計語言
- **來源**：Apple Newsroom（2025-06）、HIG「What's new」（2025-06～2025-12 多次更新）、MacRumors／AppleInsider。**可信度：高**。
- **規範要點**：
  - 玻璃只屬於「控制與導覽層」（tab bar、toolbar、sidebar、浮動按鈕），**內容層不做玻璃**；兩層分離是核心原則。
  - Tab bar 改為**浮動、半透明、隨捲動縮小**；導覽列的按鈕群組化成膠囊；圖示建議用 SF Symbols 7（新增 Draw 動畫與漸層渲染）。
  - 可及性：系統「減少透明度」會讓玻璃變霧面並遮蔽背景；「增加對比」會加粗邊緣；「減少動態」關閉液態形變。App 必須對三者都有回應。
  - 2025-09 更新材質與動態指引；2025-12 Dynamic Type 新增強調字重規格。
- **對本產品檢查項**：
  - PWA 在 iOS 上**不會自動得到** Liquid Glass；若自行用 `backdrop-filter` 仿作，只用在底部導覽與頂部工具列，卡片／題目內容區不得玻璃化。
  - 玻璃層後方若是燕麥底＋松綠插畫，文字需在**最差背景**下仍達 4.5:1；並用 `@media (prefers-reduced-transparency)` 改為實色（Safari 已支援）。
  - 底部導覽距安全區 `env(safe-area-inset-bottom)` ≥ 0，浮動 tab bar 不得壓住最後一題的「送出」按鈕。

### 1.2 HIG 2025 重點
- **來源**：Apple HIG（Accessibility／Layout／Typography／SF Symbols）。**可信度：高**。
- **規範要點**：觸控目標 **44×44 pt**；支援 Dynamic Type（至少到 xxxLarge 不破版）；安全區（iPhone 17 Pro Max 直向上 62 pt／下 34 pt）；SF Symbols 7；`Reduce Motion` 下用淡入淡出取代位移／縮放。
- **檢查項**：所有可點元件 ≥ 44 pt（Web 以 44 CSS px 估）；字級用 `rem` 並在 iOS 文字大小 200% 測試；`viewport-fit=cover` 搭配四向 safe-area inset；動畫包在 `prefers-reduced-motion: no-preference` 內。

### 1.3 Apple 對 PWA／Web App 的支援（2025–2026）
- **來源**：WebKit 部落格（Safari 26.0 功能清單、WWDC25「What's new in Safari and WebKit」）、MobiLoud／Brainhub 整理。**可信度：高（功能）／中（細節）**。
- **現況**：iOS 26 起「加入主畫面」的網站**預設以 Web App 開啟**，無安裝門檻；Web Push 自 iOS 16.4 起僅限已加到主畫面的 PWA，Safari 18.4 新增 Declarative Web Push（免 service worker）；**無** `beforeinstallprompt`，無背景同步、無 data-only push；儲存空間可能在久未使用後被清除。
- **檢查項**：提供 iOS 專用「加入主畫面」教學頁（兩步驟截圖，中文）；推播訂閱流程只在 standalone 模式顯示；本地進度以伺服器為準，IndexedDB 僅做快取；`apple-touch-icon` 180 px、`apple-mobile-web-app-status-bar-style` 配合深色模式。

## 2. Google：Material 3 Expressive、Android 16、PWA

### 2.1 Material 3 Expressive（2025-05 發布，Android 16 QPR1 於 2025-09 上線）
- **來源**：m3.material.io、Android Developers Blog（2025-05／2025-08）、Android Authority。**可信度：高**。
- **規範要點**：
  - **形狀**：新增 **35 種裝飾形狀**（供頭像、徽章、圖像群組），內建 shape-morph 動畫。
  - **動態**：spring 為基礎的 motion scheme，分「Standard」與「Expressive」兩組；Expressive 阻尼較低、有明顯回彈，只用於 hero 時刻與關鍵互動。
  - **字體**：擁抱 variable font（weight／width 軸），標題更大更重以強化層級。
  - **色彩**：動態色彩（從使用者桌布／主色擷取），強調高對比的 primary 與 tertiary 區分。
  - **元件**：按鈕群組、分段 FAB、載入指示器改為形狀變形、toolbar 浮動化。
- **檢查項**：
  - 冒險世界的「戰利品／徽章」可借用 35 形狀庫的 cookie／clover／burst 類型，但每個形狀需有 `aria-label`，不能只靠形狀傳達稀有度。
  - Spring 回彈只用於「完成一關」「升級」；答題、翻頁用 Standard；`prefers-reduced-motion` 時全部改為 150 ms 淡入。
  - 品牌色不走動態色彩，但需驗證松綠（primary）與珊瑚（tertiary）在 M3 tonal palette 的 tone 40／80 皆通過 4.5:1。

### 2.2 Android 16 自適應版面
- **來源**：Android Developers Blog（2025-01）、developer.android.com「App orientation, aspect ratio, and resizability」。**可信度：高**。
- **規範要點**：targetSdk 36 起，於**最短邊 ≥ 600 dp** 的螢幕（平板、折疊機內螢幕、Chromebook、桌面模式）**忽略** `screenOrientation`、`resizableActivity`、min/maxAspectRatio；App 必須填滿視窗，不再 letterbox。Android 17 預計擴及更多情境。
- **檢查項**：老師端平板版面以 **compact / medium / expanded**（600／840 dp）三段 breakpoint 設計；學生端 PWA 在折疊機展開（約 7.6 吋）時改為兩欄；不得用 JS 鎖定直向。

### 2.3 Web PWA 安裝與 manifest
- **來源**：web.dev「Installation」「Web app manifest」「Install criteria」（2024–2025 版）、MDN。**可信度：高**。
- **規範要點**：HTTPS；manifest 含 `name`／`short_name`、`start_url`、`display: standalone`、icons **192 + 512（any）＋ 512（maskable，內容置於中央 80% 安全區）**；建議加 `screenshots`（含 `form_factor: wide` 與 `narrow`）與 `description` 以得到 Chrome 的「豐富安裝介面」；`id` 欄位固定；`theme_color` 與 `background_color` 依深色模式各自處理。
- **檢查項**：DevTools → Application → Manifest 無警告；Lighthouse「Installable」全綠；maskable 圖示在圓形／方圓形遮罩下松綠底不裁切；`shortcuts` 提供「今日任務」「複習」兩個捷徑。

## 3. 無障礙

### 3.1 WCAG 2.2（W3C，2023-10 Recommendation；2025 成為 ISO/IEC 40500 更新版）
- **可信度：高**。新增 9 條成功準則（並移除 4.1.1 Parsing）：
  | 準則 | 等級 | 要點 |
  |---|---|---|
  | 2.4.11 焦點不被遮蔽（最低） | AA | 鍵盤焦點不能被固定頁首／底部導覽完全遮住 |
  | 2.4.12 焦點不被遮蔽（強化） | AAA | 完全不被遮住 |
  | 2.4.13 焦點外觀 | AAA | 焦點框 ≥ 2 px 粗、與背景 3:1 |
  | 2.5.7 拖曳動作 | AA | 拖曳必須有單指點擊替代 |
  | 2.5.8 目標尺寸（最低） | AA | ≥ **24×24 CSS px** 或足夠間距 |
  | 3.2.6 一致的求助 | A | 求助入口在各頁相同相對位置 |
  | 3.3.7 重複輸入 | A | 同一流程不再要求重填 |
  | 3.3.8 可及的驗證（最低） | AA | 登入不得只靠認知測驗（CAPTCHA、記憶）|
  | 3.3.9 可及的驗證（強化） | AAA | 連物件辨識也不行 |
- **檢查項**：浮動 tab bar 下方加 `scroll-padding-bottom`；拖曳配對題提供「點 A 再點 B」替代；排行榜小圖示 ≥ 24 px；每頁右上固定「求助／問老師」；登入用 LINE／Google OAuth 或 magic link，**不用 CAPTCHA**；焦點框用珊瑚色 2 px 實線＋1 px 白邊。

### 3.2 WCAG 3.0 草案方向
- **來源**：W3C WCAG 3.0 Working Draft（2025-09 修訂；2026 另有新草案的報導）、AbilityNet。**可信度：高（方向）／中（時程）**。
- **方向**：以 **Outcomes**（約 170 餘條）取代 success criteria；條款分「核心需求／補充需求／assertions（組織承諾）」；**Bronze／Silver／Gold** 取代 A／AA／AAA；CR 預估 2027 Q4 後，**2028 前不會成為正式建議**。現階段仍以 WCAG 2.2 AA 為稽核基準。

### 3.3 歐盟無障礙法（EAA，Directive 2019/882）
- **來源**：歐盟官方、Level Access、Inside Global Tech。**可信度：高**。2025-06-28 起生效，技術標準 **EN 301 549**（含 WCAG 2.1 AA＋原生 App 條款）；涵蓋電子商務、電子書、消費者端 App。非歐盟企業對歐盟使用者提供服務亦適用；微型企業（<10 人且營收 <200 萬歐元）部分豁免。對本產品：若未在歐盟上架，**非強制**；但 EN 301 549 可作為原生包裝（TWA／Capacitor）版的對照表。

### 3.4 台灣：網站無障礙規範 2.0 與教育部
- **來源**：數位發展部「無障礙網路空間服務網」、NCC 逐條說明 PDF。**可信度：高**。
- **要點**：規範 2.0 於 2016-08-15 實施、2019-08 全面使用標章 2.0；4 原則、12 指引、A／AA／AAA 三級，對應 WCAG 2.0；政府與學校網站需取得 **AA** 標章（多所國中校網已通過）。
- **教育部對學習平台**：查到「教育體系資通安全暨個人資料管理規範」（2020-09）與「教育部個人資料保護管理要點」（2019-12），要求直接蒐集兒童個資需有適當安全措施；**未查到**教育部對民間學習平台的無障礙硬性要求。若要進入校園採購（如教育部數位學習平台名單），建議預先達到規範 2.0 AA 並自我檢測。
- **檢查項**：用數位發展部 Freego 2.0 自動檢測跑一次；老師端桌機版達 2.0 AA（鍵盤可操作、替代文字、表格標題）；學生端至少 A 級且主要流程 AA。

## 4. 兒少設計與隱私

### 4.1 英國 Age Appropriate Design Code（ICO，2020 生效；2023 遊戲設計 Top Tips；2024–2025 持續稽核）
- **可信度：高**。15 項標準，核心：**預設最高隱私**、資料最小化、**不得用 nudge 讓兒童降低隱私或延長使用**、預設關閉地理位置與個人化、資料共享須證明符合兒童最佳利益。遊戲指引特別點名：隨機獎勵（loot box）需風險評估並**揭露機率**、限時優惠針對兒童需評估、要設計「自然停止點」協助脫離長時間遊玩。
- **對遊戲化的具體建議**（綜合 ICO、UNICEF、Fairplay 等）：
  | 機制 | 風險 | 建議作法 |
  |---|---|---|
  | 連勝（streak） | 損失厭惡、焦慮、半夜上線 | 允許「凍結」與「休息日」，斷連不清零只降級；22:30 後不計入 |
  | 倒數計時 | 壓力、衝動 | 僅用於限時測驗，不用於購買或獎勵；可關閉 |
  | 推播 | 打擾睡眠、FOMO | 預設關閉；可選 1 日 1 則；22:30–07:00 靜音；不用「你的角色在哭」等情緒勒索文案 |
  | 排行榜 | 社交比較、羞辱 | 預設只顯示「自己 vs 上週的自己」；班級榜需老師開啟且匿名化（暱稱＋頭像） |
  | 戰利品／轉蛋 | 類賭博 | 不含付費隨機；若有隨機掉落必須公開機率且不可用真錢加速 |
  | 虛擬貨幣 | 混淆價值 | 僅學習行為取得，不可購買 |

### 4.2 美國 COPPA 2025 修訂（FTC）
- **來源**：FTC Final Rule（2025-04-22 公布，2025-06-23 生效，**2026-04-22 完全遵循期限**）、Latham、DWT、White & Case。**可信度：高**。
- **要點**：擴大「個資」定義（含生物特徵、政府 ID）；**第三方揭露需另行取得可驗證家長同意**；用於訓練 AI 需獨立同意；須有書面保留政策、禁止無限期保留；安全計畫要求更具體；新增家長同意方式（如文字簡訊＋）。**教育科技（學校代同意）與推播限制的提案未納入最終規則**。
- **對本產品**：若有美國使用者才強制，但「第三方揭露另行同意」「保留期限」是好實務。

### 4.3 加州 AADC（CAADCA）現況
- **來源**：Ninth Circuit 2026-03-12 判決（Cooley、DLA Piper、Hintze）。**可信度：高**。2025-03 地院全面禁制 → 2026-03 第九巡迴**縮小禁制**：覆蓋定義與年齡估計條款可生效，但「資料使用限制」與「dark pattern 禁令」因模糊仍被禁；案件發回地院。狀態：**部分生效、持續訴訟**。

### 4.4 UNICEF RITEC（Responsible Innovation in Technology for Children，2022–2024）
- **可信度：高**。RITEC-8 框架：自主、能力感、情緒、關係、創造力、身分、安全、多元包容；7 項設計原則：歡迎、增進想像、開放式遊玩、**不商業剝削**、確保安全、允許實驗、符合年齡。RITEC Design Toolbox 提供自評表。

### 4.5 Apple／Google 對 13 歲以下與家長同意
- **來源**：Apple「Helping Protect Kids Online」白皮書（2025-02）、WWDC25 Session 299、iOS 26 Declared Age Range API、iOS 26.2 德州法 API；Google Play Families Policy、Family Link。**可信度：高**。
- **要點**：Apple 13 歲以下必須用 Child Account（家庭共享）；App 可透過 **Declared Age Range API** 取得年齡區間（<13／13–15／16+）而非生日；App Store 年齡分級改為 4+／9+／13+／16+／18+。Google Play 以兒童為目標的 App 須遵守 Families Policy（只能用自我認證的廣告 SDK、須申報目標受眾）。
- **對本產品**：國中生 12–15 歲，橫跨 13 歲門檻；PWA 不走商店審核，但若日後包裝上架，需填寫目標受眾與隱私營養標示（Apple Privacy Nutrition Label、Google Data Safety）。

### 4.6 教育類 App 的隱私標示
- Apple App Privacy Details（2020 起）與 Google Data Safety（2022 起）均要求列出蒐集項目、用途、是否與第三方共享；教育類常被抽查的是「分析 SDK」與「崩潰回報」是否標示。**檢查項**：隱私頁以國中生能讀的中文（國小六年級閱讀程度）說明；家長版透過 LINE 推送的通知內容**不含學生成績細節**（避免 LINE 端外洩）。

## 6. 視覺趨勢 2026 與反趨勢

- **來源**：多篇趨勢整理（Midrocket、ThePlusAddons、Brucira 等）、Apple／Google 官方發布。**可信度：中**（趨勢屬觀察）。
- **主要趨勢**：
  1. **Liquid Glass 與材質感**：2026 趨向「薄而克制」的透明層，只做導覽層。
  2. **Bento grid**：以重要性決定格子大小；適合老師端儀表板。
  3. **大字體／編輯感排版**：標題 32–48 px、字重對比；中文需注意行高 1.6 以上。
  4. **有機形狀與 blob**：呼應 M3 Expressive 35 形狀；冒險世界地圖可用。
  5. **3D／立體圖示與手繪插畫回潮**：兩者並存，手繪更適合「溫暖學習」調性。
  6. **深色模式預設／dark-first**：以表面高度（surface elevation）而非純黑分層；燕麥底在深色模式需轉為暖灰（如 `oklch(22% 0.01 80)`），不是冷黑。
  7. **低飽和柔和配色**：松綠／珊瑚／蜂蜜金屬此路線，但按鈕與狀態色仍需達對比。
  8. **動態品牌（motion identity）**：一組固定的 easing／時長／角色反應，成為品牌資產。
  9. **AI 生成內容標示**：歐盟 AI Act 2026-08 起對生成內容透明度要求生效；教育產品應標示「AI 提示」「AI 出題」並可回報錯誤。
- **反趨勢（要避免）**：過度玻璃化造成文字不可讀；低對比的「柔和」變成 WCAG 不及格；過多 spring 回彈讓國中生分心；全站 blob 失去資訊層級。
- **檢查項**：深色模式用 3 層表面（底／卡／浮層）而非單一黑；柔和配色先過 4.5:1 再談美感；AI 產生的講解卡有固定角標；動態規格書寫入設計 token（`--motion-standard: 300ms cubic-bezier(.2,0,0,1)`）。

## 7. 教育與遊戲化產品標竿（各 1–2 句可借鏡）

- **Duolingo（Rive 角色系統，2024–2025）**：角色用 Rive State Machine，8 頭×8 身組合出 64+ 中性變化、20+ 口型，單檔 <1 MB，依答題結果切換狀態。**借鏡**：冒險世界的夥伴角色用 1 個 Rive 檔＋狀態機，答對／答錯／久未操作各一組反應，而非多張 GIF。
- **Khanmigo（Khan Academy）**：蘇格拉底式只給引導問題；缺點是「裸聊天」讓缺乏先備知識的學生挫折。**借鏡**：AI 助教提供「我想要提示／我想要解法／我想要例子」三個明確按鈕，不只開放式對話框。
- **Apple Swift Playgrounds**：左碼右景、即時視覺回饋、關卡化任務。**借鏡**：每題給即時、具體的視覺回饋（而非只有對／錯），並以「任務卡」切分章節。
- **Headspace**：每個顏色、插畫、動畫服務單一情緒目標（降低焦慮）；手繪圓潤角色。**借鏡**：錯題畫面用溫和色與語氣，不用紅色閃爍。
- **Finch**：無懲罰、無排行榜，離開數日只收到鼓勵；寵物成長與自我照顧綁定。**借鏡**：連勝中斷不清零；回來時角色說「歡迎回來」而非「你錯過了」。
- **Pokémon Sleep**：刻意不獎勵「特定時段」以免誘使熬夜；獎勵與健康行為同向。**借鏡**：22:30 後不給額外獎勵，改為「明早再來有加成」，和自動轉暗配套。

## 8. 裝置現況（2026）

- **iPhone 17 系列（2025-09）**：17／17 Pro 6.3 吋（402×874 pt）、iPhone Air 6.5 吋、17 Pro Max 6.9 吋（440×956 pt，@3x）；直向安全區上 62／下 34 pt；Dynamic Island 佔頂部。**可信度：高**（Apple 規格頁、Use Your Loaf）。
- **Android**：主流 6.1–6.9 吋，最常見 CSS viewport 360×800、390×844、412×915。**可信度：高**（StatCounter／BrowserStack）。
- **台灣行動 OS 占比（2026-05）**：iOS 約 56–57%、Android 約 43%；青少年細分**未查到**。**可信度：中**。
- **折疊機**：2025 全球出貨占比約 1.5–2.5%，Samsung 占 64%；2026 預估成長 20%。**可信度：高**。
- **台灣校園**：教育部「生生用平板」2022–2025 投入約 200 億元、61 萬台（iPad、Chromebook、Surface、筆電混用）；偏鄉一人一台、非偏鄉每 6 班 1 套；報導指出多數鎖在充電車。機型占比**未查到**官方數據。2025-09 起校園手機管理新規（上課收管）。**可信度：中**。
- **平板設計要點**：iPadOS 26 以可自由調整大小的視窗取代 Split View，Stage Manager 開放所有機型；Scribble 可在任何標準文字欄位手寫轉文字；Android 16 禁止鎖定方向。**檢查項**：老師端在 600–1024 px 寬度皆可用（視窗可被縮到一半）；手寫批改區用 `<canvas>` 搭配 `pointerType === 'pen'` 區分手掌；避免依賴 hover。
