# 產品審視 0.6：架構、角色成長、帳號、隱私

三個視角各自審過 Demo（產品架構、視覺與資訊架構、用戶壓力測試），以下是結論、已做的第一批，以及要拍板的事。

## 審視發現的真相

- **巡邏每題都被強制錄音。** 題目改成變體引擎後，解說文字和「要錄音」共用 `why` 欄位，原設計只有第 2 題要錄。已修，錄音旗標改成 `askWhy`。
- **隱私前後不一致。** 設定頁寫「隊友畫面不出現名字」，首頁「隊友剛剛」卻顯示名字。已修。
- **第一週沒有設計。** 收服最快第 7–12 天才發生，Demo 從第 3 週開始把空白藏起來了；新用戶第一週圖鑑全是迷霧、家長也收不到信。第一批先補了「正在追的怪」與第一晚家長信，完整的第一週流程列在下一批。
- **「我」沒有家。** 身分、職業、成長散在各頁，職業只在隊旗上一個字，手機上進不了設定。
- **家長信用了遊戲語言。** 概念稿寫「不把遊戲語言放進家長端」，信裡卻有「收服、漏項獸、林老師週四處理」。

## 要 Edward 拍板

1. **要不要顯示等級數字（Lv）。** 建議不要，維持「階級名＋卡框」；要的話，概念稿「不做」清單第 1 條要改寫。
2. **要不要做金幣或星砂。** 建議不做；若要，只在學會時給、只能換外觀、不能買、不能抽。
3. **大人真人照的來源。** 嚮導、老師、家長用真人照，只放在大人溝通的畫面（嚮導的信、嚮導視角、營地來信、公會長）。來源二選一：你提供有授權的照片，或用 AI 產虛構人物並標「人物照為示範」（會用到 Figma 方案的付費點數）。
4. **孩子能不能看到別人的冒險者卡。** 建議看不到，只有自己、家長、嚮導看得到，避免互相比較。

## 0.7 追加：學習與遊戲的平衡、降低認知負擔

研究與量測在 `docs/research/學習與遊戲的平衡、首次體驗與漸進解鎖.md`。已做：第 1 天只有「今天」「我」與四個元素；分頁改成今天、這週、我；系統依天數解鎖；名詞白話化；小陪收成「卡住了？」。

研究對待拍板事項的補充：

- **Lv 數字**：Khan 用技能點推 Level、只升不降，是可行做法；若要顯示，只用收服數換算，刷題不會漲。
- **金幣／星砂**：Deci 等人的統合研究、Prodigy 與 Blooket 的經驗都指向「通用貨幣會驅動刷量」；第一版仍建議不做。
- **看別人的角色卡**：建議只開放小隊內互看，卡上只放圖鑑、稱號、階級，不顯示練習量、不做跨隊排行。
